# Project Agent Instructions

## Project boundaries

- This repository provides the Rust `cps` core and CLI, plus a macOS-oriented Tauri 2 desktop app. The desktop backend depends on the root `cps` crate.
- Keep provider, configuration, credential, model-discovery, and recovery behavior in the shared core where practical. Avoid duplicating that behavior in the CLI or desktop adapters.
- Treat `README.md` as the source of truth for user-facing commands, supported behavior, architecture overview, and build and distribution instructions.

## User data and secrets

- The CLI and desktop app can modify the user's Codex configuration and macOS Keychain. During routine development and automated validation, use the existing temporary-file, fixture, fake-store, and test-store patterns. Do not exercise credential, provider-switching, or restore mutations against the real user profile or Keychain unless the task explicitly calls for live integration testing and the affected state is deliberately safeguarded.
- Preserve the configuration transaction guarantees: retain unrelated settings and formatting, create recovery backups as designed, and do not overwrite external changes detected during a mutation.
- Never expose credentials, API keys, or sensitive configuration values in logs, test output, diagnostics, or committed files. Preserve the project's secret-redaction behavior.

## Development and validation

- The root Rust crate contains the shared application, provider, configuration, credential, model-discovery, and CLI modules. For relevant Rust changes, run `cargo fmt --check` and `cargo test`.
- The desktop frontend is under `apps/desktop`. Its package scripts provide `npm test` and `npm run build`; run the checks relevant to frontend changes from that directory.
- For changes to the Tauri backend under `apps/desktop/src-tauri`, run `cargo fmt --manifest-path apps/desktop/src-tauri/Cargo.toml --check` and `cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml` when the host has the required Tauri/macOS prerequisites. Also run the root-core checks when shared `cps` behavior is affected.
- Follow `README.md` for native macOS packaging. A successful local build alone does not establish that an artifact is ready for distribution.
- Do not edit generated Tauri files under `apps/desktop/src-tauri/gen/` or `apps/desktop/src-tauri/permissions/autogenerated/` by hand. Update their source configuration and regenerate them through the project's supported Tauri workflow when needed.

## Project records

- Treat `apps/desktop/*-REPORT.md` as historical build, handoff, or review evidence. Do not treat recorded branch names, commit IDs, or status statements as current instructions; check the live repository state.
- Follow the signing, notarization, and distribution limitations documented in `README.md`. Do not describe a local package as an official release based only on a successful build.
